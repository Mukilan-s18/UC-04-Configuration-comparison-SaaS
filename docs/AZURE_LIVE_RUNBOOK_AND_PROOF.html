4. Test Credentials & Security Governance Review

4.1. Authentication Architecture (Bearer Tokens vs. Username/Password)

API-First SaaS Standard: Conforming to the Advantix SaaS Challenge specifications (UC-04) and B2B SaaS best practices, ConfigGuard implements token-based Bearer authentication (Authorization: Bearer <token>). This architecture enables deterministic, automated validation by test harnesses and CI/CD pipelines without brittle interactive login forms or CAPTCHAs.

Zero-Friction Web Evaluation: Human evaluators testing the browser interface do not need to type usernames or passwords. The navigation header includes a Tenant Session Selector dropdown (Tenant A - Operator, Tenant A - Viewer, Tenant B - Operator, Tenant B - Viewer, Tenant C - Suspended) that automatically passes verified session credentials to in-browser API calls.

4.2. Pre-Seeded Test Sandbox Accounts

Tenant A (tenant-a) — Pro Tier

  • Plan: Pro (Full diff comparison and validation enabled)
  • Daily Quota: 10 runs / calendar day (Resets automatically at 00:00:00 UTC)
  • Subscription Status: Active
  • Operator Token: tenant-a-operator (Full write/execute permissions)
  • Viewer Token: tenant-a-viewer (Read-only access to audit runs)

Tenant B (tenant-b) — Basic Tier

  • Plan: Basic (Rule validation R1–R4 enabled; diff processing blocked with 403 Forbidden without quota debit)
  • Daily Quota: 3 runs / calendar day (Resets automatically at 00:00:00 UTC)
  • Subscription Status: Active
  • Operator Token: tenant-b-operator (Can execute validate runs)
  • Viewer Token: tenant-b-viewer (Read-only access)

Tenant C (tenant-suspended) — Suspended Account

  • Plan: Basic
  • Subscription Status: Suspended (All batch runs rejected with 403 Forbidden; historical reads permitted)
  • Operator Token: tenant-suspended-operator
⚠️ Security Governance & External Email Advisory:
1. Isolated Sandbox Scoping: The credentials listed above are synthetic test tokens provisioned exclusively for the Advantix student evaluation sandbox (rg-advantix-sandbox-dev). They possess zero privileges outside this demo application.
2. Credential Transmission Policy: In compliance with enterprise data security guidelines, reusable production credentials must never be transmitted via unencrypted email attachments to external company addresses. Enterprise production deployments require federated Identity Providers (e.g., Azure Entra ID / OAuth2 OIDC) or encrypted secret channels (e.g., Azure Key Vault Secret references, ephemeral one-time secret links).
3. Credential Revocation/Rotation: In this Container App environment, tokens can be instantly revoked or rotated by updating Container App environment configuration via the Azure CLI (az containerapp update --set-env-vars ...) or triggering a new container revision with zero downtime.
